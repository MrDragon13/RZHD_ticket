# Политика работы с фрагментированными данными РЖД

Документ для **разработчиков**: фиксирует договорённости по слою вагонов (5764 / `get_train_carriages`) и по отображению схемы мест, чтобы при следующих циклах доработок не переизобретать правила.

## 1. Частичные суммы по полкам (`berth_totals`) и доступность (`berth_available`)

Иногда РЖД отдаёт **не полный** набор счётчиков по нижним/верхним/боковым полкам для вагона — только фрагмент (например сумма только по части купе или по двум отсекам).

**Правило занятости:** если мы уже построили полную схему мест под тип вагона (купе / плацкарт / СВ), а из РЖД пришли суммы меньше числа мест на схеме:

- считаем, что **свободными остаются только те места, которые явно разрешены данными `berth_available`** в пределах переданного фрагмента;
- для мест на схеме **за пределами** этого фрагмента (или при отсутствии числа свободных по категории) считаем их **занятыми / проданными**.

Реализация на frontend: `mergedCarriageDetailForLayout`, `berthAvailableMergedForPartialLayout`, затем `applyOccupancyFromRzd` в `frontend/app.js`.

## 2. Фрагмент списка мест и «вместимость вагона»

Ответ по местам может описывать **кусок вагона** (например **8 полок** = два смежных 4‑местных купе). Это **не** означает «вагон на 8 мест».

**Правило схемы:** такие значения **нельзя** использовать как полную вместимость вагона для построения одной «мини-схемы» из 8 мест.

- На frontend типичная вместимость для купе берётся из метаданных поезда; малые числа из РЖД (< порога целостности) **не подменяют** типичную раскладку — см. `carriageCapacityForClass`, `berthTotalsLookLikeWholeCarriage`, `carriageCapacityFromRzd` в `frontend/app.js`.
- На backend при агрегации max вместимости по купейным вагонам из слоя 5764 игнорируются подозрительно малые значения вместимости одной записи — см. `aggregate_from_carriages_payload` в `backend/app/services/rzd_carriage_parse.py`.

Итог: **фрагмент в данных РЖД трактуем как ограничение по свободным местам и по объёму ответа, а не как новый тип «вагон на N мест»**, если N не согласуется с классом и полным составом.

## 3. Где не дублировать логику

| Область | Файлы |
|--------|--------|
| Занятость при частичных `berth_*` | `frontend/app.js` — блок вокруг `mergedCarriageDetailForLayout` |
| Порог «полных» сумм для доверия к `berth_totals` | `berthTotalsLookLikeWholeCarriage` |
| Порог вместимости поезда из слоя 5764 | `rzd_carriage_parse.py` — `aggregate_from_carriages_payload` |

При изменении любого из этих мест стоит перечитать этот файл и обновить таблицу/пороги здесь при необходимости.

---

### English summary

When RZD returns **partial** berth totals or a **partial seat list**, treat **unspecified seats as sold** relative to our full layout, and **do not** interpret small fragment sizes (e.g. 8 berths) as the whole car’s capacity—keep typical class capacities unless RZD clearly reports a full-car sum above agreed thresholds.
